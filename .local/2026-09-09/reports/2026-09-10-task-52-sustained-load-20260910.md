# Task 52 — configurable sustained multi-worker load

## Status

**PARTIAL — task-owned practical run passed; the ten-minute production target was not run.**

This update adds a checked-in command-line entry point and configurable warm-up
and measured intervals to the existing PostgreSQL multi-worker acceptance test.
The command starts its own two loopback Uvicorn workers, creates synthetic data
in the pytest database, and runs the existing 100-per-class classroom,
reconnect/restart, and assessment-resilience checks together. It rejects a
non-loopback base URL or PostgreSQL host before pytest creates rows.

## Scope and changed files

- `tests/acceptance/live_load.py` — validated CLI wrapper with the required
  `--base-url`, `--classrooms`, `--participants-per-class`,
  `--warmup-seconds`, and `--duration-seconds` options, plus interval and relay
  timeout controls.
- `tests/test_multiworker_classroom.py` — worker-zero port selection from the
  validated URL, sustained write rounds, separate warm-up/measured timing,
  per-round idempotency keys, and durable revision/ledger reconciliation.

No migrations, package production settings, host files, service processes,
shared Python installations, or xcWebServer resources were changed.

## Environment and topology

- Baseline before this update: `f445002`.
- Shell: zsh; conda environment `django`; `/data/p/bin` prepended to `PATH`;
  `PYTHONPATH=.:src`.
- Database: task-owned PostgreSQL test database selected by
  `LIVECLASSROOM_POSTGRES_TEST_NAME`; workers use `tests.postgres_settings`.
- Workers: exactly two task-owned Uvicorn/Channels processes on
  `127.0.0.1:18520` and a second automatically selected loopback port.
- Synthetic workload: two independent classrooms, 100 guest participants per
  classroom, no existing users or teaching sessions, HTTP submissions with
  idempotency keys, WebSocket relay samples, one worker restart, and HTTP state
  recovery. The assessment test adds two independent authenticated runs with
  autosave, no assessment sockets, restart recovery, expiry, and grading.

```zsh
  --base-url http://127.0.0.1:18520 \
  --classrooms 2 --participants-per-class 100 \
  --warmup-seconds 5 --duration-seconds 10 \
  --interval-seconds 2 --relay-timeout-seconds 45
```

## Limits and next step

This is local package evidence. The practical run does not establish the
requested 600-second sustained interval, broader hardware/version coverage,
host deployment, browser usability, or production/load guarantees. A later
authorized run can pass `--warmup-seconds 60 --duration-seconds 600` on a
quiescent task-owned PostgreSQL instance and retain its log; no host service
should be targeted.
